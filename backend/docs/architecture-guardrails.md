# 架构护栏

## 当前底座
`MediaCrawler` 是公开内容采集底座，适合承接：
- 视频/评论/创作者采集
- 线索入库
- WebUI 与 API 展示
- 代理、登录态、任务调度

## 我们要在上面加的东西
1. 线索管理
2. 私信工作台
3. AI 草稿生成
4. 人工确认发送
5. 回复同步与跟进

## 分层原则
### 1. 采集层
只做采集、解析、入库，不掺杂销售逻辑。

### 2. 业务层
做线索评分、标签、状态流转、分配。

### 3. 消息层
只处理会话、草稿、发送结果和回执。

### 4. AI 层
只做建议、摘要、改写和分类，不直接替人执行高风险动作。

## 需要长期保持的边界
- 平台适配代码不要侵入业务逻辑
- CRM 逻辑不要反向依赖具体平台页面
- 私信发送必须可审计
- 账号和浏览器上下文必须隔离
- 每一个任务都要能追踪来源和结果

## 交付口径
后续任何功能如果不能回答下面三个问题，就先不要做：
- 它属于哪一层？
- 它的数据从哪来，流向哪去？
- 它如何被审计和回滚？
