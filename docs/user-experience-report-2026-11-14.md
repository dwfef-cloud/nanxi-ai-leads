## 二、Bug 清单（按严重程度排序）

### BUG-01（P0，已修复）多账号隔离把存量登录态「隔丢」→ 采集 0 条
- **操作步骤**：评论获客启动任务（账号 3732e4b2…）→ 搜索「火锅」
- **预期效果**：翻到视频、采集评论
- **实际效果**：搜到 0 条视频，21 秒「任务正常完成」。对照实验：同一关键词不带账号走默认分区 **5.5 秒搜到 2 条真实视频** ——登录态在默认分区，而任务按 accountId 打开的独立分区里没有 cookie，抖音弹登录墙
- **复现率**：必现
- **修复**：壳端分区解析升级为带持久化绑定的 `resolvePartition`（存量账号自动沿用默认分区，显式登录过的账号绑独立分区，绑定落盘重启不丢）；同时加强登录墙识别。修复后连续 4 次真机采集全部成功（78/80/80/76 条评论）

### BUG-02（P0，已修复，与 BUG-01 同源）失败被吞成「正常完成」
- **操作步骤**：同上
- **预期效果**：采不到应说明原因
- **实际效果**：登录墙弹出时壳的检测选择器全部落空，任务以「正常完成 0 条」收场，用户无从知道要去重新登录
- **复现率**：必现
- **修复**：登录墙增加文本特征兜底识别；现在轨迹会明确报「抖音账号未登录（搜索页弹出登录墙）。请到『账号池』找到该账号重新登录」

### BUG-03（P1，已修复）任务运行中，实况大屏永远空屏
- **操作步骤**：启动评论获客任务 → 刷新页面/重开软件 → 切到实况大屏
- **预期效果**：任务卡片 + 滚动轨迹 + 窗口画面区
- **实际效果**：空屏「暂无需要监控的窗口」。根因：评论获客走的执行引擎不进运行时注册表，大屏的三个数据通道（画面 viewKeys、运行中清单、任务列表）全部看不见它——只有刷新前的内存状态，刷新即失明
- **复现率**：必现
- **修复**：三个通道并入活跃线程真相（`consume-*-live-preview` / `get-running-entity-leadgen-task-ids` / `get-active-automation-tasks` / `get-entity-leadgen-tasks` 仅运行中的）。修复后真机复验：卡片、轨迹、窗口区全部出现

### BUG-04（P1，已修复 2026-11-14 18:45）评论获客的统计与执行历史不落库
- **操作步骤**：跑完任务 → 看任务列表统计 / 执行历史
- **预期效果**：统计有数字；执行历史有记录
- **实际效果**：任务记录 stats 全 0、runs 只有启动配置；执行历史里 7 次运行全部缺席。对账目前只能靠线索库和运行日志抽屉
- **复现率**：必现
- **修复**：task_runner 引擎接入统一运行时证据链——启动写 `runtime_runs`（执行历史）、每个关键词一轮 `runtime_cycles`（展开明细）、结束回写任务记录的 `stats/runs/status/endedAt`；执行历史页新增「评论获客」tab；结束说明补充「重复跳过 N 条」避免「新增 0 条」被误读为白跑
- **真机复验**：任务 lea_e3e460290972（71s）→ 执行历史出现「评论获客」记录（completed、2 视频/10 评论/重复 10）；任务记录 stats/runs/endedAt 全部落库；每轮明细可展开。pytest 497 全绿
