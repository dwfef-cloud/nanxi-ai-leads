# 实况大屏位置与缩放修复（2026-11-15）

用户反馈视频画面偏向右下、溢出黑色视频容器并遮住右侧日志。本轮先核对 Dashboard 的现有布局，保留“顶部账号状态卡、下方视频窗口、右侧运行轨迹”，不重做前端布局。

## 原因与修改

- 页面 `getBoundingClientRect()` 返回 CSS 坐标，BrowserView 需要窗口 DIP 坐标。隔离上下文没有 `window.require`，旧前端返回未缩放的矩形，主进程直接使用后发生错位。现在主进程统一按主界面 `getZoomFactor()` 转换，保存原始矩形，避免重复缩放与舍入累积。创作/消息宿主也按同一规则处理；不使用混入系统 DPI 的 `devicePixelRatio`。
- 真实执行画面使用同源 Canvas viewer，原来的平台页面缩放不应再用于该 viewer。之前它把主界面一起缩小到约 60.375%。现在按预览标志及实际 URL 双重跳过预览页缩放，保留远程交互页的原有缩放行为。当前界面已通过桌面 Ctrl+0 恢复为 100%。
- 登录入口复用预览视图时，即使未传 URL，也会恢复导航到平台页。
- `get-view-layout` 为只读诊断通道，返回宿主缩放、内容区尺寸及实际 BrowserView 边界，便于核对前端矩形与原生图层。

相关文件：`desktop/main.js`、`desktop/live-preview.js`、`desktop/_verify/test_live_preview.js`、`desktop/_verify/verify-warmup-stop.mjs`。
