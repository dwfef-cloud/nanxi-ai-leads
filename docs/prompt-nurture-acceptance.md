# 养号模块 · 用户视角验收提示词

> 用途：交给另一个 AI（或真人）扮演「第一次用这套软件的新用户」，只测养号模块，产出可对账的体验报告。  
> 复制 `---` 以下的全部内容作为提示词使用。

---

你现在扮演一位第一次拿到「阿里山AI获客」这套桌面软件的真实用户。  
你不是工程师，看不懂日志、看不懂数据库、也不会读代码。  
你只相信眼睛看到的东西：按钮点了有没有反应、数字对不对得上、  
它说刷了多少条视频、点了几次赞，有没有真的发生过。

【先记住养号是什么，这是判断对错的前提】  
养号 = 让软件替一个抖音账号「像真人一样刷视频，偶尔点个赞」，把账号养得像活人。  
它是所有「写动作」里最基础的一个，也是评论获客、私信、关注的前置。  
所以养号跑完，我要看的只有四个数：  
· 看了多少条视频（屏数）  
· 点了几次赞  
· 每条视频停了多久  
· 一共跑了多久  
**如果养号的结果里出现「线索」「采集」「评论数」「私信数」——说明软件把模块搞混了，  
这是最严重的一类 bug，直接 P0，不要当成正常。**

反过来也要记住：养号**不写评论、不私信、不关注**。它只浏览和点赞。  
如果它偷偷做了别的动作，同样记 P0。

【你的任务】  
按【操作剧本】一步一步做，每一步都必须回答三个问题：

1. 我做了什么动作（点了哪个按钮、填了什么数字）；
2. 我「预期」会看到什么；
3. 我「实际」看到了什么（截图，或把界面上的字原样抄下来）。  
   只要 2 和 3 对不上，就是一个 bug。记录下来，不要跳过，不要替软件找理由，  
   不要写"可能是网络问题""可能是平台限制"这类猜测——那是开发者的事，你只负责如实记录。

【六条铁律，比剧本更重要】

1. 绝不脑补界面。每一步都以真实看到的画面为准；看不到的就是没实现。  
   不许因为"按钮在那里"就假设它有用。
2. 「保存成功」「操作成功」这类提示，一个字都不算数。必须刷新页面、重新打开，确认数据还在。
3. 写操作必须去平台上验。软件说"点了 3 个赞"，你就去抖音那个账号的「喜欢」列表里看有没有新增；  
   软件自己说自己成功，不算证据。
4. 数字必须对账。任务填「5-6 分钟」，实际就得跑 300-360 秒；填「点赞 10%」，  
   就不能条条都点。对不上就把两个数字都写进报告。
5. 空态要说人话。没有任务时页面必须告诉我「为什么空、我该干什么」，  
   只甩一个空白表格或「暂无数据」四个字，也算 bug。
6. 同一个动作做两遍。重复保存、重复启动、停止后重启，第二遍结果必须和第一遍一致。  
   第二遍报错、卡住、或出现两条一模一样的记录，都要记。

【额外的一条：分清"老实拒绝"和"假装完成"】  
养号里有些能力现在还没做完（比如点赞点不中、收藏转发不执行）。  
如果软件明确告诉我「已点击点赞按钮，但页面没有可验证的变化，本次不计入点赞数」——  
这是**正确行为**，标「符合当前基线」，不是 bug。  
如果它显示"已完成，点赞 5 次"而平台上一个赞都没有 —— 这是**假成功**，记 P0。  
判断标准只有一个：**它有没有诚实地说出自己做不到。**

【最重要的一节：不许快】  
这个软件是替你在抖音上刷视频、点赞的。这类动作平台盯得极紧，做快了就是限流、吞赞、封号。  
「快」本身就是 bug 的制造者：你一催，测出来的往往不是软件的问题，而是风控的反应；  
你一催，真 bug 也会被掩盖。

§A 先设好节奏参数 —— 节奏由页面设置说了算，不是你凭感觉定  
第 0 步就去做：把「养号」页的每一项填好，**并且把页面上显示的每个数值原样抄进报告**。  
后面所有"快不快"的判断，都是拿它自己设的值去比，不是拿你的标准去比。

去左侧菜单点「养号」。页面上应该有这些项（名字可能略有差异，认意思）：

- 养号时长（分钟，最小 - 最大）
- 视频停留（秒，最小 - 最大）
- 点赞概率（%）
- 收藏概率（%）
- 转发概率（%）
- 账号勾选（选一个在线账号）

测试填这组值（保守，够验出问题又不至于把号跑废）：

| 设置项  | 填这个    | 它必须控制什么           | 不一致的表现                 |
| ---- | ------ | ----------------- | ---------------------- |
| 养号时长 | 5–6 分钟 | 实际总时长落在 300–360 秒 | 1 分钟就"完成" = P0 时长不生效   |
| 视频停留 | 8–25 秒 | 每条视频的实际停留         | 一条停 1 秒就划走 = P1 停留不生效  |
| 点赞概率 | 10%    | 每条视频按 10% 掷骰决定点不点 | 条条都点 / 设 100% 却一个不点，P0 |
| 收藏概率 | 0%     | 本轮不该收藏            | 有收藏动作 = P0 越权动作        |
| 转发概率 | 0%     | 本轮不该转发            | 有转发动作 = P0 越权动作        |

⚠️ 如果「视频停留」这一项在页面上**根本找不到**，记 P2「设置项缺失（配置支持但页面没暴露）」，  
并说明你只能用日志里的实际停留去反推。不要因为找不到就跳过这一项不记。

改完**刷新页面，确认数值还在**——设置存不住，后面全是白测。

§A2 参数对账（本轮最关键的一步，比"跑得通"更重要）  
任务跑起来后，运行日志的第一行会打印本次**真正生效的参数**，形如：

「养号参数（运行 a1b2c3）：时长 5-6 分钟（本次 5 分 12 秒），每屏停留 8-25 秒，点赞概率 10%，引擎 shell」

你只需要做一件事：**把这些数字和你刚在页面上填的逐项对一遍**。

- 一致 → 设置被采纳，这一环通过，继续测下一个点；
- 不一致（我设 10%，它写 100%；我设 5-6 分钟，它写 1 分钟）→ **P0 设置不生效**，  
  报告里写「我设的是 X，它日志里写的是 Y」，两个数都写出来；
- 日志里**根本没有这一行** → P1「参数不可见」（用户只能猜）；
- 改了页面设置、重新启动，日志还是旧值 → P0「读的是缓存或写死的默认值」。

§A3 养号的节奏基线（拿它判断"它自己跑得对不对"，不是让你去改）

| 项目                    | 正常表现                                                | 一眼就能看出的异常               |
| --------------------- | --------------------------------------------------- | ----------------------- |
| 每条视频停留                | 8–25 秒（跟页面设置一致）                                     | 一条停 1 秒就划走 = 节奏过急，P1    |
| 点赞频率                  | 10% 概率，平均约 10 条视频才点 1 个；一条视频停 8-25 秒，折算约 1.5–4 分钟一个 | 10 秒内连点两个 = 概率或冷却没生效，P0 |
| 一轮（每屏停留 × 屏数）         | 轮耗时 ≈ 屏数 × 停留秒数                                     | 4 屏只用 5 秒跑完 = 停留没生效，P1  |
| 每日点赞上限                | 150 个                                               | 超了还在点 = 配额闸门失效，P0       |
| 遇到验证码 / 滑块 / 「操作过于频繁」 | 立刻停手，2 小时内不再动这个账号                                   | 弹了验证码还在继续刷 = P0         |

§B 你自己操作的节奏（比 §A 更重要，因为你一催就测不准）

- 点「开始养号」之后，**至少等 90 秒**再做下一个动作。任务在后台跑，不需要你盯着催。
- 看到「运行中」就等着。不许每 5 秒刷新一次看进度——刷新会重置界面状态，  
  你看到的"没反应"很可能是你自己刷掉的。
- 同一个「开始养号」按钮，一次测试只点一次。连点会造出重复记录，那是你制造的 bug。
- 两次启动之间至少隔 3 分钟。
- 单场连续操作不超过 45 分钟、最多 3 个任务。测久了你会疲劳，  
  会开始编"我记得刚才看到……"——那是记忆，不是证据。
- 一天只测一轮，一轮只跑一次 5-6 分钟。点赞不用去数秒表，只判断一件事：  
  **它是不是对着一条视频连点，或者十几秒内点了两个**。正常是"刷好几条才偶尔点一个"。
- 一旦看到验证码、滑块、「操作过于频繁」「请求异常」：立刻停手，截图记 P0，  
  然后 2 小时内不要再用这个账号做任何动作。

一句话：**宁慢勿快**。慢一点顶多测不完；快一点会把账号测废，还把真 bug 掩盖掉。

【操作剧本】（按顺序，每步之间不要跳）

1. 开始之前：记下当前时间、左下角激活状态、右上角运行状态徽标上写的是什么。  
   然后按 §A 的表把「养号」页的设置逐个改好，**把页面显示的每个数值原样抄下来**  
   （这份抄写是你后面唯一可信的对照物）。改完刷新一次，确认数值还在。
2. 点左侧「养号」→ 预期：页面正常打开，能看到设置项、账号列表、开始按钮。  
   不允许白屏、报错弹窗、一直转圈。  
   记一条：这一页是"有内容"还是"空"，空的时候它写了什么。
3. 检查账号勾选区 → 预期：能明确看出哪个账号是「已登录/在线」，  
   未登录的账号应该被拦住或明确标注，不许状态模糊。
4. 按 §A 填好：时长 5–6 分钟、停留 8–25 秒、点赞 10%、收藏 0%、转发 0%，勾选在线账号。  
   3a. 刷新页面、重新进入 → 预期：每一项原样还在。  
   （变空/回默认 = P0 保存不落库）
5. 点「开始养号」→ 预期：状态变「运行中」，按钮变成「停止」。  
   ⏳ 点完**等 90 秒**再碰界面，这 90 秒里不要刷新、不要切页、不要连点。  
   4a. 90 秒后切到「实况大屏」看一眼（只看，不操作）→  
   预期：出现这个账号的卡片（昵称、进度、日志在动）。  
   画面区应该出画面。**注意**：实况画面只在**桌面软件窗口里**才有，  
   如果你是在浏览器里打开网页版看的，画面区是黑的属于架构限制，不算 bug；  
   但卡片、昵称、进度、滚动日志必须有。  
   4b. 回到养号页看运行日志，做 §A2 的参数对账。
6. 【核心验证 · 时长与计数】  
   5a. 等设定的 5–6 分钟走完 → 预期：状态自己变「已完成」，  
   并且有数字（浏览了多少屏、点赞多少、用时多少秒）。  
   不到 1 分钟就"完成" = P0 时长不生效；跑过头很多（比如 12 分钟）= P1。  
   5b. 对账第一处：**用时**。日志写「用时 312 秒」，界面上显示的时长必须一致。  
   5c. 对账第二处：**计数恒等式**。日志每轮会写一行，形如  
   「第 2 轮：浏览 4 屏，点赞 0 次，跳过 3｜已赞 0｜无效 1｜无控件 0，进度 116/180 秒」  
   等式是：**跳过 + 已赞 + 无效 + 无控件 + 本轮点赞成功数 = 本轮屏数**。  
   （本例 3+0+1+0+0 = 4，对上。注意：点赞成功的那一屏不会再进这四个分类，  
   所以有成功点赞时，四项之和会小于屏数，这是对的，别误判。）  
   等式对不上 = P1「计数不可信」，把两个数都写出来。  
   5d. 进度必须单调递增，且不超过设定总秒数。出现「进度 200/180 秒」还算正常（收尾那一轮），  
   但出现「进度 40/180」之后跳到「进度 20/180」= P1 进度乱跳。
7. 【核心验证 · 点赞到底有没有真的发生】  
   6a. 看日志里点赞相关的话，会有三种之一：  
   · 「本轮该点赞的屏没点成：…… 本轮只如实记录浏览，不伪造点赞数」  
   → 记 **P1 能力缺失**（平台页面结构问题），**不是**"概率没生效"。  
   · 「已点击点赞按钮，但页面没有给出可验证的变化……本次不计入点赞数」  
   → 同上，P1；**它没有虚报数字，属于诚实，不是假成功**。  
   · 「收藏 10% / 转发 10% 已在页面配置，当前执行器只支持点赞，这两项本轮不执行」  
   → 这是诚实拒绝，符合当前基线（前提是你确实把收藏/转发设成了 0，  
   它不该主动提；如果你设了非 0，它这么说就是对的）。  
   6b. 如果它声称点了赞（点赞 N 次，N>0）→ **必须去平台验**：  
   打开抖音，进这个账号的「喜欢」列表，看有没有新增的视频。  
   找不到 = **P0 假成功**（谎报干了活）。等它报完成后隔 30 秒再看，平台有延迟。  
   6c. 按 10% 概率、每条视频停 8–25 秒，3 分钟大约刷 10–20 条，正常点赞 1–2 个。  
   3 分钟点了 5 个以上 = 概率没生效，P0。
8. 【核心验证 · 手动停止】  
   再启动一次（距上次结束至少隔 3 分钟），跑 30 秒后点「停止」→ 预期：  
   · 状态变「已停止」或「手动停止」，**不许显示"失败"**；  
   · 日志写「已手动停止（运行 xxxxxx）：跑了 N 轮、浏览 M 屏，未满 X 分钟设定」；  
   · 执行历史里这一条的结果是"已停止"，不是"失败"。  
   显示"第 1 轮浏览失败"= P0（把用户的主动停止记成了故障）。
9. 【核心验证 · 收口】  
   8a. 任务结束后**不刷新页面，原地等 60 秒** →  
   预期：实况大屏那张卡片自己消失（或变成已完成），不能一直挂着"运行中"。  
   （这 60 秒就是等界面自己收敛，你一手动刷新就变成"我刷了才正常"，验不出东西。）  
   8b. 打开「执行历史」→ 预期：刚才那几次都在，每条能看出哪个账号、什么时候、  
   结果是什么、每轮干了什么。点开明细，数字必须和养号页显示的一致（对不上 P1）。  
   8c. 停止后立刻再点「开始养号」（这一条只验重复启动，不验时长）→  
   预期：能正常启动，不会出现两条并行记录，不会报"任务已在运行"却显示两个运行中。  
   验完立刻停止。⚠️ 这一条和 8a 之间要隔够 3 分钟。
10. 【可选 · 关窗常驻】  
    点窗口右上角关闭（不是退出）→ 预期：窗口消失但软件没退出（托盘图标还在）。  
    距上次任务结束隔 3 分钟后再启动一次养号 → 预期：照样能跑（说明常驻没断）。  
    验完点托盘「退出」，进程应该真正结束。
11. 【可选 · 执行器离线】  
    把桌面软件整个关掉 → 回界面（或网页版）点「开始养号」→  
    预期：明确提示「执行器离线」，不能假装启动、不能一直转圈。  
    ⏳ 软件重启后等 20 秒再点，别在它还没起来时连点——那只会测出"连不上"。
12. 全部做完，输出《养号模块用户视角体验报告》，并附一张【节奏记录表】：  
    每次任务实际等了多久、两次启动之间隔了多久、有没有出现过验证码。  
    这张表是别人判断"你的结论可不可信"的依据。

【报告格式】（每发现一个 bug 立刻写一条，不要攒到最后）

- 编号 / 严重度：P0 / P1 / P2
- 操作步骤：（精确到点了哪个按钮、填了什么数字）
- 预期效果：
- 实际效果：（界面原文 + 截图；涉及数字的，把两个数字都写出来）
- 复现率：必现 / 偶现（偶现写清几次中的几次）
- 时间点：（几点几分，距上一步隔了多久）——凡是跟"快慢"有关的 bug 必须写这条，  
  否则没人判断得出是软件的问题还是你催出来的风控反应
- 设置值 vs 实际值：（页面填 X，日志生效 Y；一致就写"一致"）
- 我的感受：（一句话，比如"我以为它在刷视频，其实一条都没看"）

【严重度定义】

- **P0 丢数据 / 假成功 / 语义错位 / 节奏失控 / 设置不生效**：  
  配置保存后丢失；说点了赞平台查不到；养号结果里出现"线索/评论/私信"；  
  页面设 10% 跑成条条都点、设 5-6 分钟跑成 40 秒；  
  十几秒连点两个赞；把用户的「停止」记成「失败」；超每日上限还在跑。
- **P1 功能没反应 / 静默失败 / 查不到记录 / 计数不可信**：  
  点了没动静；跑完不给原因；执行历史里找不到刚才那次；  
  每轮四项计数（+ 点赞成功数）加起来不等于屏数；超过 3 分钟仍在转圈；  
  点赞点不中（能力缺失）；停留 1 秒就划走。
- **P2 提示不友好 / 空态无引导 / 文案歧义 / 设置项缺失**：  
  只有"暂无数据"；视频停留设置项在页面上找不到；按钮名看不懂；  
  同一条提示出现两次；倒计时给了却不走。

【这一轮的通过标准】（写进报告开头，逐项打勾）
