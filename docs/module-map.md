## 一、一句话区分

- **评论获客**：我去别人视频下**留言**，把人引过来 → **写**
- **线索采集**：我去别人视频下把**留言的人捞出来** → **读**

方向相反，配置字段、执行动作、结果统计完全不同。

## 三、评论获客的真实链路

### 配置（壳页面字段）
任务名称、执行账号、搜索关键词/话题、**视频数、互动总上限、关注上限、私信上限**、人设（AI 生成用）。

### 执行步骤
1. 按关键词搜索视频（壳 `search-videos`）
2. 逐条打开视频 → 定位主评论输入框（坐标每次实时计算，不缓存）
3. 生成评论内容（人设 AI，失败宁可跳过也不套模板）
4. 逐字输入（80–200ms 随机）→ 停顿 20–27s → 提交
5. 记账：`已发表 / 已经评过 / 人设不匹配 / 发表失败 / 未派发`
6. （可选）对评论区用户互动：点赞 / 回复 / 关注 / 私信 / 分享主页
7. 冷却 **300–600s 随机**（实测 409/509/365s）后再做下一条

### 结果统计（必须是这些键）
`published`（已发表）、`interacted`（已互动）、`reached`（已触达）、`already`（已评过）、`failed`（发表失败）、`skipped`（其它跳过）——**不是** `videos/comments/leads`。

### 写入安全
发送结果三态：`sent_ok / sent_fail / uncertain`。`uncertain`（超时、5xx、200 空响应）必须停止重试 + 告警 + 人工确认，防止重复评论。

## 五之二、顺带修掉的一个 P0 回归（同日）

排查归位后「线索采集」真机失败（`搜索页脚本无响应`）时发现：

- **根因**：注入页面的脚本里写了单反斜杠正则（`bodyText.replace(/\n+/g,'')`）。在 JS 模板字符串中 `\n` 会被求值成真实换行，注入后正则被切断，页面抛 `Invalid regular expression: missing /`。
- **为什么难查**：Electron 的 `executeJavaScript` 只回一句 `Script failed to execute`，真实错误在渲染进程控制台。
- **修复**：
  1. 两处正则改为 `\\n` / `\\s`（模板内双反斜杠）；
  2. `evaluate()` 外层包 try/catch，页面异常以返回值带回，日志能读到真实 stack；
  3. 采集窗口监听 `console-message` 与 `render-process-gone`，页面报错与渲染进程崩溃直接落 `_verify/agent.log`。
- **复验**：搜索「火锅」返回 2 条真实视频（作者/标题正常）；线索采集任务 25.3s 完成（2 视频 / 10 评论 / 重复 10 去重）。

## 五之三、养号：设置项 → 后端 → 平台动作（2026-11-14 晚，真机验证）

用户问的是「前端不是有设置多长时间点赞一次吗，后端是不是照这个设置跑」。核对下来是三处断点：

### 1. 参数名对不上（设置等于没设）
| 页面设置 | 前端字段 | 旧 runner 读的键 | 结果 |
|---|---|---|---|
| 养号时长 60-120 分钟 | `nurtureDurationMin/Max` | `cycles`（默认 1） | 跑 1 轮 6 屏就"完成" |
| 视频停留 8-25 秒 | `stayMin/stayMax` | `dwellMs`（默认 1800） | 每条停 1.8 秒 |
| 点赞概率 10% | `nurtureLikePercent` | `likeMax`（默认 0） | 一个赞都不点 |

修复：`run_warmup` 两套键都认、页面字段优先，并把**生效参数**写进运行日志第一行
（`养号参数：时长 5-6 分钟…每屏停留 8-25 秒…点赞概率 10%`），用户可逐项对账。
监控任务的 `intervalSecondsMin/Max` 同样接上（每轮在区间内重新随机）。

### 2. 养号被评论获客门禁挡住（P0）
页面养号和评论获客共用 `start-task` 通道，之前统一转给 `task_runner` 门禁 →
点「开始养号」只会得到「执行器未接入」。现在按 `taskMode` 分流：
`nurture` → 存 warmup 任务（扁平配置包进 `configSnapshot`）→ `registry.start("warmup")`；
`stop-task` 按 `nurture_` 前缀走 `registry.stop`。

### 3. 点赞点不到（平台结构）
- 抖音 PC 首页/精选（`/jingxuan`）用混淆类名，点赞节点**没有 `data-e2e`/`aria`**，
  全页只有「读屏标签」「搜索」两个真 button → 选择器方案必然 0 赞。
- 视频详情页（`/video/<id>`）里存在 `DIV.…likeIcon…`，`[class*="likeIcon"]` 可命中。
- 因此养号点赞按「详情页」实现，并且**点击后必须校验 class/计数是否变化**，
  没变化记 `click-no-effect` 不计入点赞数（不伪造）。
- 同一视频本次只点一次（重复点=取消赞）。

真机复验：预算 60 秒 → 实际 64-67 秒结束；6 轮浏览 6 屏；点赞 1 次（同视频不重复）；
收藏/转发概率已配置但执行器不支持，日志明文写「本轮不执行，不会假装做过」。

### 4. 顺带修掉：长指令被判"执行器掉线"（P1）
壳是串行执行、执行期间不轮询，`AGENT_ALIVE_WINDOW_S=30` 一到就判 `engine=none` →
一条 44 秒的养号指令跑着，后面 6 轮全部报「桌面壳未加载采集执行器」。
修复：`desktop_commands` 增加「在飞指令」判定，有指令在跑就不判掉线（420 秒兜底防泄漏）。

## 七、实况大屏黑屏修复（2026-11-14 21:10，P0）

**现象**：实况大屏窗口卡片永远是纯黑（`.window-content/.popup-body` 底色就是 `#000`），
桌面壳里也黑、浏览器里也黑。

**根因**：页面有两套 viewKey，拼法对不上——
- `init-automation-view`（账号级）：`douyin_<账号id>`；
- `update-automation-bounds`（任务级，大屏只推坐标）：`entity_/monitor_/publish_<账号id>`。
壳只做精确匹配 → `autoViews.get("entity_123")` 落空 → 返回「view not inited」→
原生视图从未挂载，用户看的就是黑色占位区。

**修复（desktop/main.js）**：
1. `viewKeyAccount/resolveAutoView`：先精确命中，再按账号后缀归一（各前缀都指向同一账号视图）；
2. 自愈：坐标到了但视图不存在 → 按 `douyin_<账号id>` 补建（宁可多一张只读视图，不给黑屏）；
3. `attachAuto` 无坐标时先给 1×1（原来默认铺满整窗会盖住页面）；
4. 新增 `focus-automation-view`（setTopBrowserView）；
5. **实况跟随**：`douyin_agent.liveState(accountId)` 返回采集窗口当前 URL 与 busy 状态；
   壳每 4s 把「正在跑任务的账号」的实况视图跟随加载到同一页——看到的是正在做的事，不是死首页；
6. 诊断日志：`desktop/_verify/live-view.log`（512KB 自动截断）。

**验证**：SHELL_LIVE_SELFTEST 自测（已移除）：`entity_selftest` → 归一 → 挂载 →
capturePage 得 760×460 真实渲染画面（非黑）。浏览器里依旧看不到画面——那是结构限制
（原生 BrowserView 叠不进浏览器页面），桌面壳里才有效。

## 八、养号「卡住」修复（2026-11-14 21:40，P0/P1 混合）

**现象**：点了开始养号，界面一直停在「养号初始化…」，进度不动；实况大屏卡片一直「运行中」；
任务结束后也不消失。

**实测事实**：DB 里任务其实跑完了（4 轮 24 屏、用时 389s、0 点赞），但页面无任何反馈。
所以是**界面拿不到真实运行态**，不是执行卡住。

**三处根因**：
1. **进度事件从未发过**：页面只认 `automation-data` 里的 `{type:"nurture-progress", payload:{...}}`，
   后端只发 `self-warmup-task-event`。账号卡片停在启动时写死的「养号初始化…」。
2. **`get-active-automation-tasks` 形状与语义都错**：返回的是「库里 status=running/pending 的
   任务 id 字符串」——① 表里有 66 条 9 月遗留 pending 行，大屏永远有卡片；② 页面读 `y.taskKind`
   全是 undefined，养号运行列表每次同步被清空。
3. **重启留僵尸**：进程退出不写 ended_ms，`runtime_runs.status` 永远 running。

**修复**：
- `runners._nurture_event()`：开跑 + 每轮结束推 `nurture-progress`（真实屏数/剩余分钟/当前动作）
  与 `nurture-actions`（点赞/收藏/转发统计）；
- `aggregate.active_automation_tasks()`：改为只认活线程（registry + task_runner），按账号聚合，
  返回 `{id(账号), taskId, taskKind, viewKey, name, nickname, durationMin/Max}`；
- `store.reap_stale_runs()` + `bridge_server` 启动钩子：把遗留 running/cycle 收尾成 aborted；
- 新增 3 项回归测试（进度事件必发 / 僵尸记录必收尾 / 历史行不算运行中），全量 **504 passed**
  （3 failed 为环境缺 patchright，与本次无关）。

真机验证：1 分钟零点赞任务 → 第 1 轮结束即收到 `nurture-progress{videosWatched:3,...}`；
`get-active-automation-tasks` 运行中返回完整对象、停止后 4 秒内变空。

## 九、养号日志重做 + 引擎钉住（2026-11-14 22:30）

**用户反馈的日志长这样**（一次 5 分钟养号刷出十几行噪音，真正进度被挤没）：

```
运行时已启动（触发方式：manual，引擎：shell）
养号参数：时长 1-1 分钟（本次 1 分 0 秒），每屏停留 6-8 秒，点赞概率 0%
已下发指令 warmup-watch（），等待壳回传…
第 1 轮完成：浏览 6 屏，点赞 0 次（概率跳过 0、已赞过 0、点了无反应 0、无点赞按钮 6）（已跑 205/300 秒）
本轮所有视频都没定位到点赞控件：抖音网页版用混淆类名…（每轮重复一遍）
第 1 轮浏览失败：已手动停止        ← 手动停止被记成失败
```

**改成（同样的运行）**：

```
养号参数（运行 2b37ff）：时长 1-1 分钟（本次 1 分 0 秒），每屏停留 4-5 秒，点赞概率 10%，引擎 shell
第 1 轮：浏览 2 屏，点赞 0 次，跳过 0｜已赞 0｜无效 0｜无控件 1，进度 17/60 秒
第 2 轮：浏览 2 屏，点赞 1 次，跳过 1｜已赞 0｜无效 0｜无控件 0，进度 35/60 秒
养号已跑满设定时长：4 轮、浏览 8 屏，用时 71 秒
养号结束（运行 2b37ff）：4 轮，浏览 8 屏，点赞 0 次，用时 71.4s
```

**具体改动**
1. 一行参数带 `运行号`（run_id 后 6 位）+ 引擎，多次运行不再串在一起分不清；
2. 去掉重复的「运行时已启动」（养号自己那行已含全部信息）；
3. 不再逐轮输出「已下发指令 warmup-watch（）」——空括号 + 每轮刷屏；
4. 轮次日志压成一行，进度写 `已跑/总秒数`，可直接和页面设置对账；
5. 「点不到赞」只在首次出现时解释一次，并给出具体原因（控件缺失/无视频链接/点了无变化）；
6. 手动停止不再记成「第 1 轮浏览失败」，cycle 记 `stopped`，结束语写「未跑满设定时长」；
7. 计数兜底：除「成功/明确跳过」以外的标记都算「想点没点成」，不再出现「四项全 0 但点赞 0」的鬼数据。

**顺带修的真 bug**
- **同一次运行中途换引擎**：`browser.execute` 每条指令重新判引擎，壳心跳有 30s 窗口，
  长指令跑着时会断一下 → 同一轮养号一半跑在壳里（用户登录态）、一半跑在独立浏览器里
  （另一份会话）。日志里夹着的「独立引擎执行 warmup-watch：成功」就是这个。
  现在 `Ctx.engine` 在启动时钉住，整轮不换。
- **注入脚本失败无法定位**：以前页面脚本一抛错，Electron 只回
  「Script failed to execute」。现在①注入前跑 ping 自检（带重试，避开窗口刚建时的加载期），
  ②WARMUP_JS 整体包 try/catch 把真实错误带回来。
- **模板字符串吃转义**：`/\/video\/\d{6,}/` 写进模板字符串后变成 `/ /video/ d{6,}/`
  → 语法错误。已改成 `indexOf` 判断，并新增 `desktop/_verify/check_warmup_js.js`
