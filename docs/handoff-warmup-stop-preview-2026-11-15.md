# 养号停止与实况修复（2026-11-15）

接续 `handoff-live-acceptance-2026-11-15.md`。用户手测反馈：从实况大屏停止不了养号，开始后几分钟看到的仍是首页。

后续用户反馈截图预览闪烁，已改为解码完成后绘制到保留旧帧的 Canvas，并将采样提高到最多每 200ms 一次。最新修改和真机证据见 [实况大屏闪烁修复](handoff-live-preview-flicker-2026-11-15.md)；下文每 1.2 秒更新等描述为此前版本记录。

## 已确认原因

- 大屏通过 `stop-task {viewKey: douyin_<accountId>}` 停止账号；原后台只停止评论获客线程，遗漏 runtime 中的养号、线索采集、监控。
- 原队列取消只中断后台等回执，桌面端串行执行期间收不到取消，注入的停留/切换继续运行。
- 实况曾用同会话的另一张抖音页跟随网址；推荐流并不把当前视频编号写入网址，预览可能重回精选首页且反复刷新，不能代表执行现场。
- 大屏文字只在一轮结束时更新，已经播放视频时仍可能显示“正在打开推荐流”。

## 本轮修改

- `registry.stop_account` 按账号停止 runtime，`stop-task` 同时覆盖两个注册表；不影响其他账号。
- 指令取消保留可查询状态；独立于串行取指令的取消心跳将停止送到桌面。取消/超时后的迟到成功回执不计成功。
- 页面停留每 100ms 检查停止标志，取消时暂停视频；停止后同时拦截播放器 `play()` 调用和 `play` 事件，覆盖平台异步自动恢复及尚未挂入文档的播放器。下一次养号移除拦截并还原播放方法；命令标识防止旧脚本影响新任务，释放后的迟到心跳也不能取消新指令。
- 连续浏览复用推荐流，不再每一轮刷新。冷启动跳过空白页探测，页面尚未完成导航时不截图、不读取播放进度。
- 实况用只读截图显示同一账号真实执行窗口，每 1.2 秒更新；超时显示画面中断，空闲保留最后画面并标明空闲。不是另开一条推荐流。
- 真实播放核实后推送“正在播放视频”，不把加载成功冒充浏览数。
- 自动养号的点赞保持默认关闭。收藏、复制仍未接入自动编排，本轮不增加平台互动。
