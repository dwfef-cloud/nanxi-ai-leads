## 二、Bug 清单

### P0-1【已修复】写操作启动请求被前端静默丢弃 → 「假运行中」

- **操作**：养号页勾选账号 → 点「▶ 开始养号」。
- **预期**：后端出现任务记录、运行记录、日志。
- **实际**：界面变「养号运行中」+ 停止按钮 + 大屏出卡片，**后端 tasks / runtime_runs / 日志零记录**，等 2 分钟仍是零。复现率 2/2。评论获客的「保存并启动」走的是同一条通道（`send("start-task")`），同样中招——这解释了此前「点评论获客大屏没反应」的一类现象。
- **根因**：`ui/live-bridge.js` 的 `send()` 只把请求转发给演示假桥，**从不发 HTTP**；而养号页、评论获客页的启动/停止全部用的 `send`。
- **修复**：`send()` 与 `invoke()` 同路径（POST `/ipc/{channel}`，单向语义只体现在不回传结果）；`index.html` 给桥接脚本加 `?v=` 版本参数，防止浏览器拿旧缓存脚本（修复后第一次复测就栽在缓存上）。
- **复验**：修复后 UI 点「开始养号」→ 后端立刻出现任务 `nurture_..._1794659337251`、运行 `war_72925461bece`、日志「养号参数：时长 5-6 分钟（本次 5 分 57 秒），每屏停留 8-25 秒，点赞概率 10%」；「保存并启动」→ 任务落库 + 运行记录 failed（诚实拒绝，见 P0 通过项）。

### P1-1 任务结束后运行状态不自清

- 养号 20:35:40 结束后：顶栏仍挂「养号运行中…」、新建任务表单里账号仍标「运行中」不可选、大屏幽灵卡片在刷新前保留；硬刷新后状态从 localStorage 恢复、仍显示运行中一次。手动「停止」或刷新页面后自愈。
- 建议：后端运行态变化时推送/轮询对账，页面 hydrate 时用后端状态覆盖本地。

### P1-2 执行历史存在永远「running」的僵尸记录

- `war_55a2b069b06f`（19:55:36 启动）至今显示 running——当时后端进程被替换，运行没走收尾。建议：启动时把「进程启动前仍为 running」的记录标记为 interrupted。

### P1-3（能力缺失，非概率问题）推荐流/精选页点赞点不到

- 两轮养号（24 屏、30 屏）点赞均为 0，日志每轮明示「没定位到点赞控件……能力限制不是概率问题」，并附页面诊断（data-e2e 候选清单）。软件没有伪造点赞数，诚实；但「点赞概率 10%」这个设置在首页场景永远等于 0，用户会以为是坏了。建议：养号默认走视频详情页（详情页有 likeIcon 可命中）。

## 五、四问

1. **最不敢用的功能**：「运行中」状态本身——P0 修复前它和后端完全脱节，修好后仍存在「结束不自清」，我不敢凭界面绿字判断任何事，只能去执行历史对记录。
2. **只修一个 bug**：live-bridge `send` 丢弃请求（已修）。它是「点了没反应」这类用户投诉的总根源。
3. **点了不知道会发生什么**：「保存并启动」成功后自动跳大屏（这个反而清楚）；评论获客表单下半区在对话框里滚不出来，填了什么心里没数。
4. **催过它吗**：没有。所有启动间隔 ≥3 分钟（实际最短 6 分 12 秒），养号跑满 5–6 分钟才动下一步。全程无验证码、无平台异常提示。
